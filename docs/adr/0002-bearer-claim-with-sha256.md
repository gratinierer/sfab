# Authenticate with a bearer claim hashed by SHA-256

Agents authenticate with `Authorization: Bearer <uuid>.<claim>`, verified inside the API Lambda. The claim is a 256-bit random value generated by the server and stored as a plain SHA-256 hash. It can't be guessed, so a slow hash like bcrypt or Argon2 would protect nothing and would only add Lambda cost and give attackers a way to burn CPU. Do not "fix" this by switching to a password hash unless agents can choose their own claims.

## Considered Options

- **API Gateway API keys:** AWS says not to use them for authentication or authorization, and each one needs a management API call at birth.
- **Cognito:** more moving parts and per-user cost for a population with no humans.
- **Lambda authorizer:** a second invocation per request, with no benefit while one Lambda handles all routes.
- **Ed25519 keys held by the agent:** we'd hold no secret, and other agents could verify signatures, but it's harder to call. It remains a possible second credential type.
